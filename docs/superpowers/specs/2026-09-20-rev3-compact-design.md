# minidrone_fc rev3 (compact) 設計仕様

- 日付: 2026-09-20
- ブランチ: `rev3-compact`
- 成果物: KiCAD 回路図 + PCB レイアウト（ERC / DRC 通過まで）+ 4層製造データ
- 基準: rev2.1 (`rev2.1-fab` タグ) からの作り直し

## 1. 背景と目的

rev2.1 は **50 × 64 mm・取付穴 44 × 44 mm** で、これは業界標準の
フライトコントローラ取付ピッチ（16/20/25.5/30.5 mm）のいずれにも該当しない。
そのため市販フレームに載せられず、フレームを自作する以外に選択肢がなかった。

rev3 の目的は **市販フレームに載る標準ピッチの小型基板にすること**。
回路の機能は rev2.1 を踏襲しつつ、面積を占めている部品を置き換える。

rev2.1 で面積を食っていたもの:

| 部品 | rev2.1 | 原因 |
|---|---|---|
| GY-521 モジュール | 約 21 × 16 mm | IMU をブレイクアウト基板ごと搭載していた（チップ本体は 4 × 4 mm） |
| XIAO ESP32C3 | 21 × 17.8 mm | スルーホール実装のため裏面もピン2列分塞ぐ |
| 電解コンデンサ ×2 | 直径 6.3 mm | 基板下側 17 mm の張り出しの主因 |

## 3. 主要な設計判断とその理由

### 3.1 XIAO → ESP32-C3-MINI-1

**XIAO は 29 mm 角に収まらない。** 幅 21 mm のスルーホールモジュールで、
14 本のピンが基板を貫通し裏面の配置スペースを塞ぐ。面積を概算すると:

- 裏面の使える面積（取付穴・XIAO ピン列を除く）: 約 675 mm²
- 部品の配線込み必要面積: 約 650〜880 mm²

6.5A を流す太い配線が必要なことも踏まえると成立しない。

MINI-1 は **13.2 × 16.6 mm の表面実装**で裏面を塞がず、重量も約 1g
（XIAO ＋ 外付け U.FL アンテナは約 4g）。基板内蔵アンテナなので、
墜落時に破損しやすい U.FL コネクタとケーブルが不要になる。

**代替案として検討し、採用しなかったもの:**

- **XIAO 維持 + 30.5 × 30.5 mm**: 30.5 mm は 5 インチ級ブラシレス機の標準で、
  ブラシモーター機のフレームではほとんど使われない。目的を半分しか満たさない。
- **XIAO 維持 + 2枚スタック**: FC 基板と電源基板を 25.5 mm ピッチで積む案。
  技術的には妥当で、ノイズ分離の点ではむしろ優れるが、高さが 6〜10 mm 増え、
  発注も 2 件になる。今回は薄さと単純さを優先した。

### 3.2 取付穴は M1.4 / 25.5 × 25.5 mm

Cockroach V3、Fractal 65 LITE、BETAFPV Air65 II などの市販フレームが
この寸法で FC を受ける。ネジは M1.2〜M1.4 で、穴径は 1.5 mm とする。

**rev2.1 および初期検討時の M2 は誤り。** Whoop 系フレームは M1.4 が標準。

### 3.3 IMU は BMI270

| | MPU-6050 | BMI270 |
|---|---|---|
| JLCPCB | C24112 / $11.06 | **C2836813 / $3.63** |
| パッケージ | QFN-24 4 × 4 mm | **LGA-14 2.5 × 3 mm** |
| 状態 | 生産終了品 | 現行品 |

29 mm 角では面積が貴重で、BMI270 は **約半分の面積かつ約 1/3 の価格**。
最近の Whoop 用 FC でも標準的に使われている。

BMI270 は **BMI160 とピン互換**なので、KiCAD 標準の `Sensor_Motion:BMI160`
シンボルと `Package_LGA:Bosch_LGA-14_3x2.5mm_P0.5mm` フットプリントを流用できる。

**注意:** BMI270 は電源投入のたびに約 8 KB の設定データを書き込む必要がある。
ハードウェアには影響しないが、ファームウェアで Bosch 公式 API か
同等のライブラリを使うこと。

### 3.4 TPS63002 (5V) → TPS63001 (3.3V)

rev2.1 は「VBAT → TPS63002 で 5V → XIAO 内蔵 LDO で 3.3V」という
二段構成だった。これは XIAO が内蔵 LDO を持つための妥協で、
効率は昇圧 90% × LDO 66% ＝ 約 60% だった。

MINI-1 は 3.3V 直結なので **TPS63001（3.3V 固定出力）で一段**にできる。
効率は約 90% に改善する。

昇降圧を使う理由は rev2.1 と同じ: 1S LiPo はモーター負荷で 3.2V 台まで沈み、
ESP32-C3 の下限 3.0V を割るため。LDO では原理的に解決できない。

### 3.5 電池側の逆流防止ダイオード（安全上の要点）

充電回路を載せないため、**USB の 5V が電池に流れ込まないようにする必要がある。**
対策しないと USB 接続時に 5V が LiPo にかかり、4.2V を超えた過充電となる。
1S LiPo の内部抵抗は 50〜100mΩ 程度で、USB 側が電流制限しても
充電終止制御なしに電流が流れ続けるため、セルの劣化・膨張・発火につながる。

**電池側にのみ**ショットキーダイオード D5 を入れる。USB の 5V が来ると
D5 が逆バイアスになり、電池には一切流れ込まない。VBUS は VSYS に直結する。

| 状態 | VSYS | 電池への流入 |
|---|---|---|
| 電池のみ | VBAT − 0.4V | — |
| USB のみ（電池なし） | 5V | — |
| 両方接続 | 5V | なし（D5 が逆バイアス） |

「USB を挿す前に電池を抜く」という運用でも危険は避けられるが、
**安全が人間の操作ミスの有無に依存する設計は避ける。**
ファームウェア開発中は USB を頻繁に抜き差しするため、
まさに間違いが起きやすい場面である。

**USB 側にはダイオードを入れない。** それが防ぐのは「電池の電力が
USB ポート側へ逆流すること」で、電源の入っていない USB 機器に
つないだ場合にしか起きない軽微な事象であり、
面積の余裕が 1 割弱しかない本基板では割に合わない。

ダイオードの電圧降下（約 0.4V @ 350mA）は**昇降圧 DC-DC の手前**なので
問題にならない。電池 3.0V − 0.4V = 2.6V でも TPS63001 の下限 1.8V より
十分高く、出力 3.3V を維持できる。

rev2.1 では同じ 0.4V の降下が致命傷だったが、それは LDO の手前だったため。

**モーター側は D5 を通さず VBAT に直結する。** D5 に流れるのはロジック系の
電流のみ（最大約 350mA）で、B5819W の 1A 定格に十分収まる。

### 3.6 IMU と気圧計を SPI 1 本に相乗り

MINI-1 の使える GPIO は 15 本で、必要な信号を数えると
I2C を別に立てると 1 本足りない。SPI を共用すれば収まる。

SPI は I2C より高速に IMU を読めるため姿勢制御にも有利。

### 3.7 意図的に載せないもの

- **充電回路**: 面積 50〜60 mm²（基板の約 7%）。市販の Whoop 用 FC も
  ほぼ非搭載で、電池は外部充電器で充電するのが一般的
- **ブザー**: 面積 25〜50 mm²

## 4. 回路構成

### 4.1 ブロック図

```
電池 (J1, PH2.0) --+---------------------------> モーター x4 (VBAT 直結)
                   |                              Q1-Q4 + D1-D4
                   +--[D5]--+
                            +--> U4 TPS63001 --> 3V3 --+--> U1 ESP32-C3-MINI-1
USB-C (J2) VBUS ------------+    (1.8-5.5V in)         +--> U2 BMI270
      D+/D- --[U5 ESD]--> U1 GPIO18/19                 +--> U3 BMP280
                                                        +--> LED1
VBAT --[R1/R2 分圧]--> U1 GPIO0 (ADC)
```

### 4.2 電源部

| 部品 | 型番 | 役割 |
|---|---|---|
| U4 | TPS63001 (VSON-10) | 昇降圧、1.8–5.5V 入力 → 3.3V 固定 |
| L1 | 2.2µH / 1.5A / 3×3mm | TPS63001 用インダクタ |
| D5 | B5819W (SOD-123) | 電池側の逆流防止。1A / Vf 0.58V@1A |
| C（入力） | 10µF | TPS63001 VIN 直近 |
| C（出力） | 22µF | TPS63001 VOUT 直近 |
| C（VINA） | 0.1µF | 制御段デカップリング |
| C（VBAT バルク） | 22µF × 3 | モーター起動時のリップル吸収。電解を積層セラミックに置換 |
| R1, R2 | 100k / 100k | 電池電圧分圧。4.2V → 2.1V |

TPS63001 のピン接続（データシート SLVS520C で確認済み）:

| ピン | 名称 | 接続 |
|---|---|---|
| 1 | VOUT | 3V3 |
| 2 | L2 | L1 の片側 |
| 3 | PGND | GND |
| 4 | L1 | L1 のもう片側 |
| 5 | VIN | VSYS（D5 の後段。VBAT と VBUS の高い方） |
| 6 | EN | VSYS（常時イネーブル） |
| 7 | PS/SYNC | VSYS（強制 PWM。Wi-Fi バースト負荷の過渡応答重視） |
| 8 | VINA | VSYS（0.1µF でデカップリング） |
| 9 | GND | GND |
| 10 | FB | **3V3（固定出力版は FB を VOUT に接続）** |
| 11 | EPAD | GND（サーマルビアで In1.Cu へ） |

### 4.3 MCU・センサと GPIO 割り当て

ESP32-C3 は **GPIO 2 / 8 / 9 が strapping ピン**で、起動時の論理レベルで
動作モードが決まる。プルアップが自然に必要な信号を意図的に割り当てる。

| GPIO | 割り当て | 備考 |
|---|---|---|
| 0 | BATT_SENSE | ADC1_CH0 |
| 1 | M1 PWM | |
| **2** | IMU_INT（BMI270 INT1） | 10k プルアップ → strapping 要件(H)を満たす |
| 3 | M2 PWM | |
| 4 | SPI MISO | BMI270 / BMP280 共用 |
| 5 | M3 PWM | ADC2 のため Wi-Fi 併用時 ADC 不可。デジタル出力に割当 |
| 6 | SPI SCLK | 共用 |
| 7 | SPI MOSI | 共用 |
| **8** | IMU_CS（BMI270） | アイドル H + 10k プルアップ → strapping 要件(H)を満たす |
| **9** | BOOT パッド ＋ 状態 LED | 下記参照 |
| 10 | M4 PWM | |
| 18 / 19 | USB D− / D+ | USB-Serial-JTAG |
| 20 | BARO_CS（BMP280） | U0RXD。起動時は入力なので競合しない |
| 21 | 予備（デバッグ UART TX パッド） | U0TXD |

**モーター PWM を 1 / 3 / 5 / 10（非 strapping）に寄せたのが要点。**
ゲートには 100k プルダウンが付くため、strapping ピンに置くと
起動時に L に引かれて書き込みモードに落ちる。

**GPIO9 の LED は必ず「3V3 → 抵抗 → LED → GPIO9」の向き（アクティブロー）
で接続すること。** 逆向き（GPIO9 → LED → GND）にすると起動時に GPIO9 が
L に引かれ、毎回ダウンロードモードで起動して動かなくなる。
この向きなら 10k プルアップと合わせて起動時 H を保てる。
BOOT パッドは GPIO9 を GND に短絡する形で併設する。

### 4.4 モータードライブ（4 チャンネル同一）

rev2.1 で実証済みの回路をそのまま使う。

- Q1–Q4: AO3400A（30V / 5.7A / SOT-23、ロジックレベル）
- ゲート直列 150Ω、ゲート–GND 間 100k プルダウン
- D1–D4: SS24 還流ダイオード（2A、モーター電流 1.62A に対し余裕あり）
- 各モーターに 0.1µF のデカップリング
- M+/M− をはんだパッドで基板四隅に配置

### 4.5 USB-C

- J2: TYPE-C-31-M-12（USB-C 16P / USB2.0 / 表面実装ライトアングル）、CC1 / CC2 に 5.1k プルダウン
  フットプリント `Connector_USB:USB_C_Receptacle_HRO_TYPE-C-31-M-12` が
  この部品専用のものなので、必ずこの組み合わせで使うこと
- U5: USBLC6-2SC6 で D+/D− の ESD 保護
- VBUS は VSYS に直結する（電池への逆流は電池側の D5 が防ぐ。3.5 節参照）

## 5. PCB 仕様

| 項目 | 仕様 |
|---|---|
| 外形 | 29 × 29 mm、四隅 R |
| 取付穴 | φ1.5 mm × 4（M1.4）、25.5 × 25.5 mm ピッチ |
| 層構成 | L1 部品・信号 / **L2 ベタ GND** / **L3 VBAT プレーン** / L4 部品・信号 |
| 板厚 | 0.8 mm |
| 設計ルール | クリアランス 0.2 mm / トレース 0.2 mm / ビア 0.6 mm・ドリル 0.3 mm |

配置の要点:

- **MINI-1 のアンテナ部は基板外形から張り出させ、その直下は全層で銅箔なし**
  （GND を残すと飛距離が大幅に落ちる）
- **BMI270 は基板中央付近、GND ベタの上**に置き、モーター電流の経路から離す
- TPS63001 のスイッチングループ（U4 − L1 − 入出力コンデンサ）を最小面積に
- U4 の EPAD 直下にサーマルビアを配置し In1.Cu の GND に落とす
- VBAT は In2.Cu プレーンで配り、モーターパッド近傍でビアを打つ
- GND スティッチングビアで B.Cu ベタと In1.Cu プレーンを結ぶ

## 8. 既知の制約

- **電池コネクタ PH 2.0 は定格 2A に対し最大 6.5A。**
  接点抵抗は 1 接点あたり約 20mΩ で、6.5A ではコネクタ部だけで
  約 0.26V の電圧降下と約 1.7W の発熱が生じる。
  ユーザーの手持ち電池に合わせた上での選択であり、既知の妥協点とする。
  改善するなら BT2.0 のケーブルをはんだパッドに直付けする方式になる
  （BT2.0 は JLCPCB では扱いがない）。
- **充電回路なし。** 電池は外部充電器で充電する。
- **位置維持（ホバリング時に横に流れない制御）はできない。**
  オプティカルフローや GPS を搭載していないため。
  姿勢安定と気圧計による高度維持までが可能。
- **BMP280 はプロペラ風の影響を受ける。** スポンジで覆うこと。
  また床から 50 cm 以内では地面効果で気圧が乱れ、高度維持は使えない。
- **rev2 用のファームウェアはそのまま動かない。**
  ピン割り当てが変わり、IMU も MPU-6050 から BMI270 に変わるため。
- **BMI270 は電源投入のたびに約 8 KB の設定データ書き込みが必要。**

## 9. 完了条件

1. Espressif KiCAD ライブラリが登録され、`ESP32-C3-MINI-1` が使える
2. 回路図が 4 章の全ブロックを含み、アノテーション済みで **ERC エラー 0**
3. 回路図から PCB が生成され、29 × 29 mm 外形・φ1.5 mm 取付穴 4 個
   （25.5 × 25.5 mm）・4 層構成が 5 章のとおり作成されている
4. MINI-1 のアンテナ直下が全層キープアウトになっている
5. 全部品が配置・配線され、GND ベタと VBAT プレーンが充填され、
   **`kicad-cli pcb drc` でエラー 0・未配線 0**
6. `kicad-cli pcb drc` の `schematic_parity` が 0
7. 4 層の Gerber / ドリル / BOM / CPL が出力され、
   JLCPCB 実装対象の部品に LCSC 品番が設定されている

## 10. 検証方法についての注意

**KiCAD MCP の `run_drc` は未配線アイテムを検査しない。**
エラー 0 でも配線が繋がっていない状態があり得るため、
最終確認は必ず `kicad-cli pcb drc` で行うこと。

**MCP の `refill_zones` は 4 層フルプレーンで 30 秒タイムアウトする。**
KiCAD 同梱の `pcbnew` Python（`D:\KiCad\10.0\bin\python.exe`）で
`ZONE_FILLER(b).Fill(b.Zones())` を直接実行して回避する。

詳細は `docs/superpowers/plans/2026-09-19-buckboost-and-4layer.md` の
「ツール上の注意点」を参照。
