# minidrone_fc — ミニドローン制御基板 KiCadプロジェクト

1S LiPo / 8520コアレスモーター×4 / 目標58g・上限70g

回路図は生成済みです。手で描く必要はありません。

---

## 1. 使い方

1. このフォルダごと `D:\KicadProjects\` などに置く（`D:\Kicad`
   の中には置かないでください。KiCad更新時に消える可能性があります）
2. `minidrone_fc.kicad_pro` をダブルクリック
3. 回路図（`.kicad_sch`）を開く

**KiCad 10で開くとファイル形式の変換確認が出ます。**
このプロジェクトはKiCad 7形式で生成されているためです。
「はい」で変換してください。以後は10形式で保存されます。

---

## 2. 最初にやること: XIAOのフットプリント設定

**U1のフットプリントは意図的に空欄にしてあります。**
XIAOはKiCad公式ライブラリに含まれず、環境によってライブラリ名が
変わるため、こちらで決め打ちできませんでした。

手順:

1. https://github.com/Seeed-Studio/OPL_Kicad_Library をZIPで取得
2. 展開し、`Seeed Studio XIAO Series Library/` 内の `.kicad_sym` を
   設定 → シンボルライブラリを管理 から追加
3. フットプリントは `.pretty` フォルダに入っていないと認識されません。
   単体の `.kicad_mod` ファイルの場合は `Seeed_XIAO.pretty` という
   フォルダを作って中に移動してから、
   設定 → フットプリントライブラリを管理 で追加
4. 回路図でU1を選択 → E キー → Footprintフィールドに
   `Seeed_XIAO:XIAO-ESP32C3-SMD` のような実際の名前を入力

U1のシンボル自体はこのプロジェクト内の `minidrone.kicad_sym` に
同梱してあるので、シンボルライブラリの導入は必須ではありません。
必要なのはフットプリントだけです。

## 4. 設計資料からの変更点

基板化の過程で判明した誤りを訂正しています。

| 項目 | 変更前 | 変更後 | 理由 |
|---|---|---|---|
| 極性コンデンサ | `Device:CP` | `Device:C_Polarized` | CPはKiCad 5時代の名前。現行ライブラリに存在しない |
| フライバックダイオード | SS14 | **SS24** | SS14は1A定格。モーター電流1.62Aに対し余裕が乏しい。SS24は2A定格で、フットプリントは同じD_SMAなのでレイアウト変更不要 |
| C3〜C6の接続先 | Qのドレイン–ソース間 | **VBAT–GND間** | 高周波電流ループを閉じるのは電源側。低側スイッチではこちらが標準 |
| PTCヒューズ・電源SW | あり | **削除** | 6.5Aでは直列抵抗による電圧降下が推力損失に直結する |

## 5. ピン割り当て（ESP32-C3の制約を反映済み）

| XIAOピン | GPIO | ネット | 備考 |
|---|---|---|---|
| D0 | GPIO2 | 未使用 | ストラッピングピン。使用不可 |
| D1 | GPIO3 | BATT_SENSE | ADC1。Wi-Fi動作中も使える |
| D2 | GPIO4 | GATE_FL | |
| D3 | GPIO5 | GATE_FR | |
| D4 | GPIO6 | SDA | |
| D5 | GPIO7 | SCL | |
| D6 | GPIO21 | GATE_RL | |
| D7 | GPIO20 | IMU_INT | MPU6050のデータレディ割り込み |
| D8 | GPIO8 | 未使用 | ストラッピングピン |
| D9 | GPIO9 | 未使用 | BOOTピン |
| D10 | GPIO10 | GATE_RR | |

**A0はD0と同一ピンです。** そしてGPIO2はストラッピングピンなので、
電圧センスはD1（GPIO3）に置いてあります。またESP32-C3のADC2は
Wi-Fi動作中に使えないため、ADC1に属するピンでなければなりません。

D7をIMU割り込みに使っているので、将来UART受信機を追加する場合は
再割り当てが必要です。

## 6. 次の手順（基板レイアウト）

1. Eeschemaで ツール → フットプリントを割り当て を開き、U1だけ設定
2. 検査 → エレクトリカルルールチェック(ERC) を実行
3. ツール → 基板エディタで基板を更新
4. 基板の外形（Edge.Cuts）を35×35mmで描く
5. 配置は以下の順序で。**この順序が重要です**
   - モーターパッド J2〜J5 を四隅に
   - Q1〜Q4 と D1〜D4 を対応するパッドの直近（5mm以内）に
   - C3〜C6 を各Qの直近に
   - U1を中央、USB-Cが基板端から出る向きに
   - U2を裏面中央、モーター電流経路を避けた位置に
6. デザインルール: 最小クリアランス0.2mm、最小トレース幅0.25mm、
   ビア0.6mm/ドリル0.3mm
7. VBATとGNDはトレースではなく**ベタ（カッパープアー）**で。
   6.5Aには1oz銅で約4.0mm幅のトレースが必要で、35mm角では引けません
8. M_FL〜M_RRは1.0mm幅以上

### レイアウトで最も重要な点

**フライバックループの面積を最小化してください。**
モーターOFFの瞬間、逆起電力が モーター → D → VBAT → モーター を
流れます。このループが囲む面積がそのままノイズの放射源になり、
MPU6050の読み値を汚します。D1〜D4は必ずモーターパッドの真横に、
ビアを挟まずに配置してください。

## 7. 未検証事項

- **XIAOフットプリントの実寸**: Seeedのライブラリで裏面パッドや
  サーマルパッドの欠落が報告されています。実物を基板に当てて
  確認してください
- **MPU6050のQFN-24実装**: 手はんだは難度が高めです。困難なら
  GY-521完成基板（+1〜2g）に戻す判断もあり得ます
- **フレーム側の穴位置**: モーターパッドの座標はフレーム設計と
  同時に決める必要があります。基板レイアウトの前にフレーム寸法を
  確定させてください
- **ガーバー出力は未実施**: 発注前にDRCとガーバービューアでの
  目視確認を必ず行ってください

## 8. rev2 での修正（ERC結果を反映）

初版に対してERCを実行した結果、エラー3件・警告137件を修正しました。

| 症状 | 件数 | 原因 | 対応 |
|---|---|---|---|
| `power_pin_not_driven` | 3（エラー） | XIAOの3V3ピンを`power_in`と定義していた。実際はレギュレータ**出力**。またGND/VMCUに駆動源が明示されていなかった | 3V3を`power_out`に修正。VBAT/GND/VMCUにPWR_FLAGを追加 |
| `endpoint_off_grid` | 133（警告） | 部品座標が1.27mm（50mil）グリッドに乗っていなかった | 全部品を1.27mmグリッドにスナップ |
| `lib_symbol_mismatch` | 4（警告） | AO3400Aは本来`extends BSS138`の派生シンボル。展開して埋め込んだためライブラリ本体と差異が出る | 下記参照 |

### lib_symbol_mismatch について

これは**動作に影響しない表示上の警告**です。KiCad 7の回路図フォーマットが
`extends` を受け付けないため、生成側で展開する必要がありました。

解消したい場合は、KiCad 10で
**ツール → シンボルをライブラリから更新** を実行してください。
埋め込みコピーがKiCad 10のライブラリ版に置き換わり、警告が消えます。
接続には影響しません。
